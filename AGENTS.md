# AGENTS.md

San Isidro College website. Astro 7 SSR + Svelte 5 islands + Tailwind v4 + Prisma 7 + Better Auth. See `README.md` for commands and `astro-migration-plan.md` for the design rules (§3) and the revision notes at its top.

## Environment

- Run everything inside `devenv shell` (NixOS: Prisma engines, Playwright browsers and MariaDB come from nixpkgs). `devenv up` = dev stack (MariaDB + astro dev), `devenv test` = full CI on a throwaway SQLite file.
- Use `vp` (Vite+) for check/test/tasks; Astro owns dev/build (`vp run dev`, `vp run build`). Never call `vp dev`/`vp build`.
- Installed agent skills: `.claude/skills/{astro,prisma-cli,prisma-client-api,prisma-orm-setup,prisma-driver-adapter-implementation}`.

## Rules

- Schema: edit `prisma/schema.base.prisma` only; keep Laravel table/column names (`@@map`/`@map`). Use `{{longtext}}` for long text columns and `{{text}}` for strings that can exceed 255 characters (URLs, tokens); on MySQL every other String is VARCHAR(255). Then `vp run db:migrate`, and add the same migration for the other providers.
- DB access: `import { db } from '@/lib/server/db'`. Public view models are defined in `src/lib/content-types.ts` and produced by `src/lib/server/queries.ts`.
- Query cost: post cards and lists never parse `content`: the Excerpt is `clampExcerpt(searchText)` (`toPostSummaries` in `queries.ts` loads `content` only for rows whose `searchText` is empty), so every writer must keep `searchText` in step. The MariaDB pool size is explicit (`src/lib/server/db.ts`: `DATABASE_POOL_SIZE` or `?connectionLimit=` in `DATABASE_URL`, default 5). Never enable Better Auth `cookieCache`: password changes and account deletion must end sessions at once.
- Rich content (posts, hero sections, the Welcome hero (`src/lib/server/welcome-hero.ts` owns its Setting key, read and write), department `hero_content`) is a JSON block document (`{"type":"sic-blocks","version":1,…}`, `src/lib/blocks/`) or legacy Markdown. Classification happens once in `@/lib/blocks/content` (`parseContent` → `html()`, `text()`, `excerpt()`, `check()`; wrappers `renderContent`, `toPlainText`, `excerptOf`, `checkContent`; `editableBlocks` turns stored content into the editor's blocks): anything opening with `{"type":"sic-blocks"` is a block document, and a broken one renders empty and is rejected on save. Never call the Markdown or block renderers directly. The one exception is the editors' live previews (`BlockEditor` canvas with `renderBlocks`, `MarkdownEditor` preview with `parseMarkdown`), which render the in-memory draft, not stored content; nothing else may. Validate on save via `contentField()` (`@/lib/server/content-field`). A Block type is one module in `src/lib/blocks/block-types/` (defaults, props schema, rules, HTML, plain text, palette meta, inline-editable fields) registered in `src/lib/blocks/registry.ts`, plus its icon and Inspector panel in `components/admin/editor/block-editors.ts` (`inspector/panels/`); both registries are compile-checked against `PropsByType`, and `registry.test.ts` runs every registered type through defaults, hostile-string escaping and plain-text checks. Never add a per-type switch elsewhere. Media blocks: `image` takes an upload or a pasted image URL (`safeImageSrc`) and an optional `link` (`safeHref`; external links get `target="_blank" rel="noopener noreferrer"` and a screen-reader hint; a linked image needs alt text); `album` (≤ `LIMITS.albumImages` images, alt required per image) renders plain links to the full images with the `data-album` hook, and `src/scripts/lightbox.ts` (native modal `<dialog>`, Esc/arrows/swipe, "n of m", focus return) upgrades them. It is a vanilla script, never an island, loaded only by `components/site/AlbumLightbox.astro`, which every public renderer of block content (`MarkdownSection`, the post page) mounts when `hasAlbum(html)`; a new public page that outputs block HTML must do the same. `video` accepts YouTube/Vimeo (iframes) or our own uploaded files (`parseVideoUrl` provider `file`: only the app route `/storage/videos/<32 hex>.mp4|webm`, which redirects to the bucket when `S3_PUBLIC_URL` is set; rendered as `<video controls preload="metadata" playsinline>`). Department `hero_content` is still edited as Markdown.
- Block editor: tree rules live in `src/lib/blocks/edit.ts` (`resolveDrop` for every palette/canvas/Layers drop, `canDrop`, indent/outdent, delete, convert Markdown) and the editing session in `components/admin/editor/session.ts` (`EditorSession`: blocks, `History`, selection that never dangles, emitted value, Layers `revision`). `BlockEditor.svelte` applies edits through the session (`session.apply(edit)`, `setProps`, `undo`, `redo`, `select`) and never mutates blocks, history or selection itself; the one columns-stack literal is in `document.ts` (`updateBlock` keeps one stack per column).
- Search over rich content uses the plain-text `search_text` columns of `posts` and `hero_sections`, never the raw `content` JSON. Every writer sets `searchText: searchTextOf(content)` (`@/lib/blocks/content`); `vp run db:backfill-search` recomputes all rows.
- Carousel slides may carry `carousel_items.overlay` (JSON `{v:1, layers:[…], mobile?}`, positions in % of the 16:9 slide, token colours/sizes; `src/lib/carousel-overlay*.ts`). A Slide without a usable overlay (legacy title/subtitle/link) is converted to Layers once, in the Slide read model (`slideDocument` in the schema; read in `src/lib/server/slides.ts`: `findSlides` for the public Carousel, `toDesignerSlide` for the designer, one `slideVideoView` for the file-or-YouTube rule), so the public Carousel and the designer render Layers only — never add a legacy render path. The Mobile layout facts (phone breakpoint, 4:5 frame, hero heights, auto text-colour rule, Layer + box → style) live in `src/lib/carousel-layout.ts`; the CSS that must repeat them is `src/styles/slide-layout.css`, and `carousel-layout.test.ts` fails when they disagree or a component hard-codes one. Validate with the overlay schema (`parseOverlayStrict` for writes, `parseOverlayDocument`/`parseOverlay` for reads); layer images live under `carousels/` and are cleaned up on update/delete. Phones (< `sm`) show the slide at 4:5: a layer's optional `mobile` override (`x`,`y`,`w`,`h` in % of the 4:5 frame, `size` token of the phone type scale, `hidden`) and the slide's `mobile.focus` (photo focal point) are optional, so every `{v:1, layers}` document written earlier parses and renders unchanged on desktop. Layers without a hand-placed `mobile.x/y` are stacked by the pure `resolveMobile` (`carousel-overlay-mobile.ts`: reading order, full width in the margins, sizes one notch down, no overlaps, shrinks to fit); the public carousel and the designer's Mobile view both use it, never a second layout rule. A slide may have a background video, either `carousel_items.video_path` (an uploaded `videos/` key owned by the row: replaced, removed and deleted only through `commitWithFiles` `stale` / `deleteWithFiles`, see `updateSlide`/`deleteSlide` in `carousel-admin.ts`, and copied on duplicate) or `video_url` (a YouTube link, played from `youtube-nocookie.com`); never both, and the required slide image stays the poster (also under `prefers-reduced-motion` and Save-Data). Actions take one `video` string (`''` = none) parsed by `parseSlideVideo`.
- Slide designer: `CarouselDesigner.svelte` renders, keeps focus and toasts, and edits only through `SlideDesignerSession` (`src/lib/slide-designer-session.ts`, free of Svelte/DOM/`astro:*`): drafts, open Slide, selected Layer, undo, dirty state (`isDirty`/`anyDirty`), Layer commands (`patchSelected` clamps to `LAYER_LIMITS` from `carousel-overlay-schema.ts`, MAX_LAYERS enforced in `addLayer`/`duplicateSelected`), and save reconcile / reorder rollback through a `DesignerPort` (the carousel actions, wired in the component). Never re-copy Layer limits or hand-edit drafts in the component.
- Org chart: `/admin/departments/<id>/members` is a visual editor (`components/admin/members/OrgChartEditor.svelte`, public look from `components/site/OrgChart.astro`). All tree logic (ordering, moves, cycle checks, reparent-on-delete) lives in `src/lib/org-tree.ts` and is shared with `actions/members.ts` (`reorder` takes `[{id, parentId, order}]` for one department in a transaction; `delete` moves direct reports up to the manager). Chart changes are drag/keyboard driven.
- Tree editors (Navigation links `NavLinksEditor.svelte`, Org chart): every structural change, and every rename or visibility patch, goes through one `createTreeEditSession` (`src/lib/tree-edit-session.ts`, free of `astro:*`): it owns the confirmed and optimistic trees, a save queue (saves run one at a time, in edit order), rollback to the last confirmed tree with the failure message/announcement returned in the `EditResult`, and undo/redo. History policy: it rolls back together with the tree after a failed save (earlier confirmed entries stay undoable; `record: false` edits and `adopt`ed changes made elsewhere stay out). The editors hand it a port (the `reorder`/`update` actions) and the tree's `ops` (`navTreeOps` in `nav-tree.ts`, `orgTreeOps` in `org-tree.ts`); never hand-roll commit/rollback/undo in an editor. A proposed nav tree is checked by `proposeNavTree`, built on the same `reorderError` the `navlinks.reorder` action runs, so editor and server give one message.
- Authorization: every action, API route and admin page calls `src/lib/server/authz.ts` first (`requireUser`, `requireSuperAdmin`, `scopeDepartment`, `scopeOwnDepartment`). Actions load rows through `loadScoped(actor, model, id)` (one row), `loadScopedMany(actor, model, ids)` (a batch: NOT_FOUND if any is missing, FORBIDDEN if any is another department's), `loadMember(actor, departmentId, id)` and `loadOwnDepartment`, and resolve the department to store through `resolveWriteDepartment` (`src/lib/server/department-access.ts`: existence check, NOT_FOUND/FORBIDDEN); never re-implement them per action. Department inputs use the shared `departmentIdField` zod schema and department `<select>` options come from `departmentOptions(actor)` (same module); never repeat either. Rejected requests are one type, `RequestError` (`request-error.ts`, free of `astro:*`; codes BAD_REQUEST, UNAUTHORIZED, FORBIDDEN, NOT_FOUND, CONFLICT, UNPROCESSABLE_CONTENT, TOO_MANY_REQUESTS): `authz` and every domain module throw only it, never `ActionError` or a hand-built `json({ message }, 4xx)`. Each entry point has one adapter: actions wrap the handler in `guarded()` (`action-guard.ts`), `/api/admin/**` routes use `adminRoute()` (`api-route.ts`), and admin/settings/dashboard pages call `adminPage(Astro.locals.user, { superAdmin?, load? })` (`admin-page.ts`, with `parseId`), which returns `{ actor, row }` or the error Response to `return`; pages never hand-roll a try/catch. `department-access.test.ts` runs against a temporary SQLite database (`src/lib/server/test-db.ts`: migrations applied, seed with Prisma, `vi.mock('./db')`); test DB-backed server code that way, not with mocked Maps. Actions wrap bodies in `guarded()` from `src/lib/server/action-guard.ts`, which also maps `RequestError` (`request-error.ts`) to `ActionError`. Admin API routes wrap handlers in `adminRoute()` (`src/lib/server/api-route.ts`).
- Admin scope: the sidebar switcher (`components/admin/ScopeSwitcher.svelte`) stores `admin_scope` (`all` | `main` | `<department id>`) in a cookie and calls `reloadView()`. Middleware resolves it on every `/admin`, `/dashboard`, `/settings` request into `Astro.locals.adminScope` via `src/lib/server/admin-scope.ts` (unknown ids → `all`; department users are pinned to their department). Paginated admin lists (posts, hero sections, departments, downloads, users) run through `runList` (`src/lib/server/admin-list.ts`): the page declares its sortable fields (`sortBy`, default direction per field), search fields and filters, and gets the page's rows, totals and the `sortHref`/`ariaSort`/`pageHref` links back (`SortableTh`/`EmptyRow`/`ListPagination` in `components/admin/shared/`: the "Pages" nav and "Showing x–y of N" come from `ListPagination`; page widths from `widePageClass`/`formPageClass` in `admin/ui.ts`); never build an `orderBy`, sort link or page clamp in a page. Other list queries filter with `departmentWhere(actor, scope)` / `listWhere(actor, scope, [search, type, …])` only (the actor's restriction always wins, and `runList` applies it through `listWhere`; `listWhere` ANDs extra filters so a search `OR` can never overwrite it; never spread a filter next to `departmentWhere`; `{ includeGeneral: true }` adds department-less rows, e.g. download directories); never add per-page department filters. Create forms preselect `scopeDefaultDepartment(scope)`. Main scope = rows with `departmentId = null`.
- Files: `src/lib/server/storage` only (`put`, `remove`, `read`, `publicUrl`, `downloadUrl`); backend chosen by `STORAGE_DRIVER` (`local` | `s3`). Store bare keys; never hard-code `/storage/` URLs. Files owned by a row are written and removed only through `commitWithFiles` / `deleteWithFiles` (`src/lib/server/stored-files.ts`): new files are removed if the DB commit fails, stale/owned files are removed only after it succeeds, and cleanup failures are logged, never thrown. Stored and served types come only from the `src/lib/server/file-types.ts` allowlist (extension decides; never trust the browser's declared type; no HTML/SVG uploads). Videos (MP4/WebM, `src/lib/video-types.ts`) are in that allowlist but only the video upload accepts them: `imageFile` has its own image list and Downloads refuse them (`isVideoUpload`). Unattached images (block/Markdown content, carousel layers) go through the one route `src/pages/api/admin/uploads/image.ts` (`acceptImage`, `image-intake.ts`; `kind` = `content` | `layer`); clients use `postImage`/`uploadImage` from `components/admin/editor/upload.ts`. Download files go through `acceptDownloadFile` (`download-intake.ts`), which accepts a multipart file or a direct-upload key: `s3` uploads downloads from the browser through presigned PUT URLs from `src/pages/api/admin/uploads/direct.ts` (server-generated key recorded in `pending_uploads` for the requesting user, signed content type + size) because Vercel rejects request bodies over ~4.5 MB; the intake checks ownership, object existence and size before claiming the pending upload (one shared check for Downloads and videos: `claimUploadedObject`, `direct-intake.ts`). The bucket needs a CORS rule for PUT from the site origin. Videos (`LIMITS.video`, 100 MB) never go through actions: clients call `uploadVideo(file, onProgress)` (`components/admin/editor/upload.ts`), which POSTs `{ fileName, contentType, size }` to `src/pages/api/admin/uploads/video.ts` (type and size check, `assertUploadQuota`, server-generated `videos/<random>.<ext>` key in `pending_uploads`), PUTs the bytes (`s3`: presigned URL straight to the bucket; `local`: the same route's `PUT`, read by hand into a temp file by `receiveUpload`, stopped and removed past the announced size, key owner only; never cancel the request body, that crashes Node), then POSTs `{ key }` to `video/complete.ts` (`video-intake.ts`: owner, object, size, then the claim) and stores the returned app URL `storageRouteUrl(key)` (`/storage/videos/<key>`, also with `S3_PUBLIC_URL`; the route redirects to the bucket base, which answers `Range`); `videoKeyFromUrl` maps either URL form back to its key. Pending-upload expiry only deletes the `pending_uploads` row, never the file (a never-completed key may already be in content); only the orphan cleanup deletes files. Both drivers implement `get(key, range)` and `/storage/*` answers `Range` with 206 / 416 so videos seek; keep that when touching the route. Keep multipart bodies small (`LIMITS.image` is 4 MB on `s3`). `local` (self-hosted, no S3) takes every other upload multipart through actions, so `security.actionBodySizeLimit` in `astro.config.mjs` (24 MB) must stay above the largest non-video limit in `LIMITS` (`e2e/uploads.spec.ts` checks the 20 MB Download); API routes are not actions, so it does not limit videos (`@astrojs/node`'s `bodySizeLimit` applies to them too: `astro.config.mjs` sets it to `VIDEO_MAX_BYTES` + 1 MB). Endpoints that store files not yet attached to a record are rate-limited per user (`assertUploadQuota`, `src/lib/server/rate-limit.ts`). Orphans are reclaimed by `storage-cleanup.ts` (`vp run storage:cleanup [-- --dry-run]`, Vercel Cron `/api/cron/storage-cleanup` with `CRON_SECRET`): it deletes files no String column of any table mentions (found from the Prisma model metadata, so new columns count automatically) once they are older than the 24 h grace, and drops expired pending-upload rows; never reference a file by anything but its key or `publicUrl`.
- Every stored image upload is WebP. The browser compresses first (`src/lib/image-compress.ts`): WebP, downscaled to a per-use box (`IMAGE_TARGETS`: slide 1920×1080, highlight/content 1600, layer 1200, logo 512, portrait 480). Croppers pass `target` to `ImageField`; other uploaders call `compressImage(file, target)`. The server then enforces it: `imageFile(maxBytes, target)` (`src/lib/server/image-file.ts`) only checks the declared type and size while the input is validated (parsed value: an `ImageUpload`, so nothing is decoded for a signed-out or failing request); `commitWithFiles` and the image intake (`acceptImage`) then call `storedImage`, which converts it inside the box with sharp (`toWebp`, `image-webp.ts`: the real format must be JPEG, PNG, WebP, GIF or AVIF, EXIF orientation, no upscaling, animated GIF → animated WebP, all metadata dropped). A fitting WebP without EXIF/XMP is kept as-is so it is not encoded twice. New image inputs must use `imageFile` with the matching target. Downloads are files, not images: never converted. Static brand images in `public/` are pre-sized WebP (`sic-seal-96.webp`, `sic-seal.webp`); `sic-seal.png` remains only for the manifest, JSON-LD logo and Open Graph.
- Image variants: each image kind has its own widths (`variants.ts`: a Highlight image `posts/<name>` 640 px, a Slide photo `carousels/<name>` 960 px) as WebPs at `<key without ext>.w<width>.webp` (`src/lib/server/storage/variants.ts` and `image-variant.ts`; written by `commitWithFiles` with `variant: true`, removed with the original by `removeAll`, kept and deleted with it by the storage cleanup). Pages use them only through `variantUrl(key, width)` (`PostSummary.imageSmallUrl` → `srcset` in `PostCard` and the Post hero, `CarouselSlide.imageMediumUrl` → `srcset` in `HeroCarousel`); `/storage/<variant>` serves the original when the variant is missing, so a missing variant never breaks a page. `vp run storage:variants` creates the missing ones for existing images (Slide photos come from `carousel_items.image_path`, as `carousels/` also holds Layer images, which have none).
- Admin/settings navigation is client-side (`<ClientRouter />` in `AppLayout`), with intent prefetch + progress bar in `src/scripts/admin-navigation.ts` (prefetched HTML is used only for plain link clicks within 15 s; forms and programmatic navigations fetch fresh). In admin islands, navigate with `navigate()` from `astro:transitions/client` and refresh with `reloadView()` from `@/lib/navigation` so the prefetch cache is invalidated; reserve `window.location` for auth changes (logout, account deletion).
- Public pages prefetch on intent: `src/scripts/public-prefetch.ts` (loaded by `PublicLayout` for anonymous visitors only) calls Astro's `prefetch` on hover (65 ms), focus or touch for links that `isPublicPage` (`request-policy.ts`) accepts; the click then reuses the `PUBLIC_CACHE_CONTROL` response. Never prefetch private routes, `/storage`, feeds or signed-in pages (`no-store`, not reusable). `prefetch.prefetchAll` stays off.
- JS-handled forms declare `method="post"` (never a default GET) so an island that fails to hydrate cannot put field values, especially passwords, in the URL. `/login` also handles that POST server-side. Admin and settings forms get their submit state (processing, field errors, message, success callback) from `actionForm()` (`components/admin/shared/action-form.svelte.ts`; pure core in `action-form-core.ts`); never hand-roll it. Auth and settings forms use it too: `fieldByCode` maps an action error code to its field (`{ CONFLICT: 'email' }`), and after a failed submit it focuses the first `[aria-invalid="true"]` control, else the `[data-form-message]` alert (`FormActions`, `Notice`). Controls get `id`, `aria-describedby` and `aria-invalid` from the `Field` snippet props (`admin/shared/Field.svelte`, `auth/Field.svelte`); never wire them by hand.
- Testable server code stays free of `astro:*` imports. Tests: `src/**/*.test.ts`, import from `vite-plus/test`. DB-backed unit tests use `test-db.ts` (SQLite through its own client in `src/generated/prisma-sqlite`, so they pass whatever provider dev uses). E2E in `e2e/` runs against a fresh database of the dev provider (`storage/e2e-<E2E_PORT>.db`, or `<db>_e2e_<E2E_PORT>` on MariaDB; `e2e/env.ts`, `e2e/reset-db.ts`) + uploads dir, never the dev database; specs take storage states from `e2e/auth-state.ts`. Parallel runs: set distinct `E2E_PORT` and `E2E_DIST` (build with `astro build --outDir <dist>`).
- Design: colours only through tokens (`src/styles/tokens.css`, Tailwind names like `bg-brand-800`, `text-primary`, `text-muted-foreground`); no hex in components. Form control borders use `border-input-border` (≥3:1, WCAG 1.4.11), not `border-border-strong`. Serif (Playfair Display) for h1/h2 only; min text size 12 px; one h1 per page; skip link + landmarks; visible focus ring.
- SEO: every public page passes `title`, `description`, canonical-safe URL, and JSON-LD where meaningful via layout props; private routes are `noindex` (request policy: `src/lib/server/request-policy.ts` owns route classes, login redirect and response headers; `src/middleware.ts` only reads the session, resolves Admin scope and applies them). Post URLs come from `postHref` (`site-nav.ts`). Page queries (`getPostPage`, `getDepartmentPage`, `getPostsPage` in `queries.ts`, `getDownloadsPage` in `downloads.ts`) return a `PageSeo` built by `src/lib/seo.ts` (`siteUrl`, `canonicalHref`, single description clamp `metaDescription`); pages pass it through instead of assembling SEO props. List filters for `/posts` and `/downloads` (parse, `postsHref`/`downloadsHref`) come from `src/lib/post-filters.ts`; `getDownloadsPage` (`src/lib/server/downloads.ts`, the one Downloads module: Tag encode/decode `encodeTags`/`parseTags`, `DEFAULT_DIRECTORY` = General for a Download without a Directory, the admin file view `toAdminDownload` and folder map `getAdminFolders`; actions and pages never re-implement them) also owns the Directory counts, folder links and the `noindex` of filtered pages, and `DownloadBrowser` only renders it (the page is not paginated: it groups by Directory with a count per group). Header, footer and the default menu come from `src/lib/site-nav.ts` (`headerItems`, `footerItems`, `DEFAULT_NAV_LINKS`, `DEPARTMENTS_MENU_URL`, `departmentHref`, `SITEMAP_PAGES`/`STATIC_PATHS`); never write a `/departments/<slug>` href, a `#departments` literal or a fallback menu elsewhere. Keep public pages free of admin bundles; hydrate islands only where needed.
- No server filesystem or in-process state (the app runs as serverless functions on Vercel): no `Astro.session`, no on-disk caches/uploads outside the `local` driver. Toasts go through `flash()` (`action-guard.ts`) = short-lived httpOnly `sic_flash` cookie read by `takeFlash` in `AppLayout`; auth rate limits use Better Auth `storage: 'database'` (`auth_rate_limits`), and app limits (password checks, contact form, uploads) use `consumeRateLimit` on the same table under `app:` keys. Current-password checks go through `assertPassword` (`password-login.ts`); changing the email requires it. A User's Password login (the `credential` Account row plus the hash mirrored into `users.password`) is created, replaced and read only through `src/lib/server/password-login.ts` (`setPasswordLogin(client, userId, hash, { endSessions })`, `endSessions(client, userId, except)` = "end the other sessions, keep mine", `currentPasswordHash`, `assertPassword`; free of `astro:*`); users create/update, account, `create-admin` and the seed use it, and nothing else touches `db.account` or `db.session` (Better Auth aside). Password minimums live only in `src/lib/password-policy.ts` (`MIN_PASSWORD_LENGTH` for Users, `MIN_ADMIN_PASSWORD_LENGTH` for `create-admin`, error/hint wording; client-safe): actions, the Better Auth config and the forms import it, never a literal. "Keep at least one Superadmin" lives in `user-rules.ts`: the check and the write run in one Serializable `superadminTransaction` (a conflict is a 409 "try again"); `users.update` demotion uses `assertUserDemotable` inside it, `users.delete` and `account.deleteAccount` call `deleteUserWithFiles` (owned files removed after the commit). Sign-in (`login.astro`'s no-JS POST), sign-out and the current session id go through `src/lib/server/auth-session.ts` (`getSession`, `signIn`, `signInFailure`, `signOut`, `currentSessionId`; `auth.api` is called only there, besides the `pages/api/auth/[...all].ts` handler mount). Mail texts (reset, verify, email-changed, contact) are composed in `src/lib/server/mail-messages.ts`; callers pass data to `sendMail`.
- Adapter: `@astrojs/node` standalone by default; `@astrojs/vercel` when `VERCEL` is set or `ASTRO_ADAPTER=vercel` (`astro.config.mjs`). `vercel.json` builds with `node scripts/prisma-schema.mjs && prisma generate && astro build` and never migrates: CI runs `prisma migrate deploy` first. Add new migrations for every provider that has a `prisma/migrations/<provider>/` folder (sqlite, mysql, postgresql), with names sorting after existing ones. Strings that can exceed 255 characters need `{{text}}` (MySQL VARCHAR(255) otherwise) or `{{longtext}}` in the base schema.
- HTTP edge and security: `middleware.ts` answers signed-out calls to any action except `contact.send` with 401 before the body is read (`rejectsAnonymousAction`; a new public action must be added to `PUBLIC_ACTIONS` in `request-policy.ts`). The CSP (`security.csp` in `astro.config.mjs`) allows scripts from `'self'` and Astro's build-time hashes only, plus two hand-hashed entries (`src/scripts/theme-init.js`, which `BaseLayout` inlines, and Svelte's `this.__e=event` img handler); never add an inline script or `on*=` attribute without a hash: `e2e/security.spec.ts` fails on any CSP violation. On Node the middleware also tags public HTML with a weak ETag (304) and gzip/brotli-compresses text (`http-edge.ts`, `__NODE_SERVER__` from the config); Vercel does both itself. Better Auth routes the app does not use are disabled in `DISABLED_PATHS` (`auth.ts`); account changes go through `actions/account.ts` only. Sign-ins are also rate limited per email (`consumeSignInAttempt`).
- Production admin bootstrap: `prisma/create-admin.ts` (`ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD` or TTY prompt; ≥ `MIN_ADMIN_PASSWORD_LENGTH` = 12 chars, deliberately longer than a User's 8). Local/self-hosted stays available; S3 is the storage backend on Vercel. No placeholder content or images; missing imagery renders a token-coloured fallback.
