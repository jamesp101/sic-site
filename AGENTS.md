# AGENTS.md

San Isidro College website. Astro 7 SSR + Svelte 5 islands + Tailwind v4 + Prisma 7 + Better Auth. See `README.md` for commands and `astro-migration-plan.md` for the design rules (§3) and the revision notes at its top.

## Environment

- Run everything inside `devenv shell` (NixOS: Prisma engines and Playwright browsers come from nixpkgs). `devenv up` = dev stack, `devenv test` = full CI.
- Use `vp` (Vite+) for check/test/tasks; Astro owns dev/build (`vp run dev`, `vp run build`). Never call `vp dev`/`vp build`.
- Installed agent skills: `.claude/skills/{astro,prisma-cli,prisma-client-api,prisma-orm-setup,prisma-driver-adapter-implementation}`.

## Rules

- Schema: edit `prisma/schema.base.prisma` only; keep Laravel table/column names (`@@map`/`@map`). Use `{{longtext}}` for long text columns. Then `vp run db:migrate`.
- DB access: `import { db } from '@/lib/server/db'`. Public view models are defined in `src/lib/content-types.ts` and produced by `src/lib/server/queries.ts`.
- Rich content (posts, hero sections, `welcome_hero_content`, department `hero_content`) is a JSON block document (`{"type":"sic-blocks","version":1,…}`, `src/lib/blocks/`) or legacy Markdown. Classification happens once in `@/lib/blocks/content` (`parseContent` → `html()`, `text()`, `excerpt()`, `check()`; wrappers `renderContent`, `toPlainText`, `excerptOf`, `checkContent`; `editableBlocks` turns stored content into the editor's blocks): anything opening with `{"type":"sic-blocks"` is a block document, and a broken one renders empty and is rejected on save. Never call the Markdown or block renderers directly. The one exception is the editors' live previews (`BlockEditor` canvas with `renderBlocks`, `MarkdownEditor` preview with `parseMarkdown`), which render the in-memory draft, not stored content; nothing else may. Validate on save via `contentField()` (`@/lib/server/content-field`). New block types need schema + renderer + plain-text + editor inspector + tests. Department `hero_content` is still edited as Markdown.
- Search over rich content uses the plain-text `search_text` columns of `posts` and `hero_sections`, never the raw `content` JSON. Every writer sets `searchText: searchTextOf(content)` (`@/lib/blocks/content`); `vp run db:backfill-search` recomputes all rows.
- Carousel slides may carry `carousel_items.overlay` (JSON `{v:1, layers:[…]}`, positions in % of the 16:9 slide, token colours/sizes; `src/lib/carousel-overlay*.ts`). Null = legacy title/subtitle/link rendering. Validate with the overlay schema; layer images live under `carousels/` and are cleaned up on update/delete.
- Org chart: `/admin/departments/<id>/members` is a visual editor (`components/admin/members/OrgChartEditor.svelte`, public look from `components/site/OrgChart.astro`). All tree logic (ordering, moves, cycle checks, reparent-on-delete) lives in `src/lib/org-tree.ts` and is shared with `actions/members.ts` (`reorder` takes `[{id, parentId, order}]` for one department in a transaction; `delete` moves direct reports up to the manager). Chart changes are drag/keyboard driven and saved optimistically with rollback.
- Authorization: every action and admin page calls `src/lib/server/authz.ts` first (`requireUser`, `requireSuperAdmin`, `scopeDepartment`, `scopeOwnDepartment`). Actions load rows through `loadScoped(actor, model, id)` (one row), `loadScopedMany(actor, model, ids)` (a batch: NOT_FOUND if any is missing, FORBIDDEN if any is another department's), `loadMember(actor, departmentId, id)` and `loadOwnDepartment`, and resolve the department to store through `resolveWriteDepartment` (`src/lib/server/department-access.ts`: existence check, NOT_FOUND/FORBIDDEN); never re-implement them per action. Department inputs use the shared `departmentIdField` zod schema and department `<select>` options come from `departmentOptions(actor)` (same module); never repeat either. `department-access.test.ts` runs against a temporary SQLite database (`src/lib/server/test-db.ts`: migrations applied, seed with Prisma, `vi.mock('./db')`); test DB-backed server code that way, not with mocked Maps. Actions wrap bodies in `guarded()` from `src/lib/server/action-guard.ts`, which also maps `RequestError` (`request-error.ts`) to `ActionError`. Admin API routes wrap handlers in `adminRoute()` (`src/lib/server/api-route.ts`).
- Admin scope: the sidebar switcher (`components/admin/ScopeSwitcher.svelte`) stores `admin_scope` (`all` | `main` | `<department id>`) in a cookie and calls `reloadView()`. Middleware resolves it on every `/admin`, `/dashboard`, `/settings` request into `Astro.locals.adminScope` via `src/lib/server/admin-scope.ts` (unknown ids → `all`; department users are pinned to their department). List pages filter with `departmentWhere(actor, scope)` / `listWhere(actor, scope, [search, type, …])` only (the actor's restriction always wins; `listWhere` ANDs extra filters so a search `OR` can never overwrite it; never spread a filter next to `departmentWhere`; `{ includeGeneral: true }` adds department-less rows, e.g. download directories); never add per-page department filters. Create forms preselect `scopeDefaultDepartment(scope)`. Main scope = rows with `departmentId = null`.
- Files: `src/lib/server/storage` only (`put`, `remove`, `read`, `publicUrl`, `downloadUrl`); backend chosen by `STORAGE_DRIVER` (`local` | `s3`). Store bare keys; never hard-code `/storage/` URLs. Files owned by a row are written and removed only through `commitWithFiles` / `deleteWithFiles` (`src/lib/server/stored-files.ts`): new files are removed if the DB commit fails, stale/owned files are removed only after it succeeds, and cleanup failures are logged, never thrown. Stored and served types come only from the `src/lib/server/file-types.ts` allowlist (extension decides; never trust the browser's declared type; no HTML/SVG uploads). Unattached images (block/Markdown content, carousel layers) go through the one route `src/pages/api/admin/uploads/image.ts` (`acceptImage`, `image-intake.ts`; `kind` = `content` | `layer`); clients use `postImage`/`uploadImage` from `components/admin/editor/upload.ts`. Download files go through `acceptDownloadFile` (`download-intake.ts`), which accepts a multipart file or a direct-upload key: `s3` uploads downloads from the browser through presigned PUT URLs from `src/pages/api/admin/uploads/direct.ts` (server-generated key recorded in `pending_uploads` for the requesting user, signed content type + size) because Vercel rejects request bodies over ~4.5 MB; the intake checks ownership, object existence and size before claiming the pending upload. The bucket needs a CORS rule for PUT from the site origin. Keep multipart bodies small (`LIMITS.image` is 4 MB on `s3`). Endpoints that store files not yet attached to a record are rate-limited per user (`assertUploadQuota`, `src/lib/server/rate-limit.ts`).
- Every stored image upload is WebP. The browser compresses first (`src/lib/image-compress.ts`): WebP, downscaled to a per-use box (`IMAGE_TARGETS`: slide 1920×1080, highlight/content 1600, layer 1200, logo 512, portrait 480). Croppers pass `target` to `ImageField`; other uploaders call `compressImage(file, target)`. The server then enforces it: `imageFile(maxBytes, target)` (`src/lib/server/image-file.ts`) converts anything that is not already a WebP inside the box with sharp (`toWebp`, `image-webp.ts`: EXIF orientation, no upscaling, animated GIF → animated WebP); a fitting WebP is kept as-is so it is not encoded twice. New image inputs must use `imageFile` with the matching target. Downloads are files, not images: never converted. Static brand images in `public/` are pre-sized WebP (`sic-seal-96.webp`, `sic-seal.webp`); `sic-seal.png` remains only for the manifest, JSON-LD logo and Open Graph.
- Admin/settings navigation is client-side (`<ClientRouter />` in `AppLayout`), with intent prefetch + progress bar in `src/scripts/admin-navigation.ts` (prefetched HTML is used only for plain link clicks within 15 s; forms and programmatic navigations fetch fresh). In admin islands, navigate with `navigate()` from `astro:transitions/client` and refresh with `reloadView()` from `@/lib/navigation` so the prefetch cache is invalidated; reserve `window.location` for auth changes (logout, account deletion).
- JS-handled forms declare `method="post"` (never a default GET) so an island that fails to hydrate cannot put field values, especially passwords, in the URL. `/login` also handles that POST server-side. Admin and settings forms get their submit state (processing, field errors, message, success callback) from `actionForm()` (`components/admin/shared/action-form.svelte.ts`; pure core in `action-form-core.ts`); never hand-roll it.
- Testable server code stays free of `astro:*` imports. Tests: `src/**/*.test.ts`, import from `vite-plus/test`. E2E in `e2e/` runs against a fresh `storage/e2e-<E2E_PORT>.db` + uploads dir (see `playwright.config.ts`), never the dev database; specs take storage states from `e2e/auth-state.ts`. Parallel runs: set distinct `E2E_PORT` and `E2E_DIST` (build with `astro build --outDir <dist>`).
- Design: colours only through tokens (`src/styles/tokens.css`, Tailwind names like `bg-brand-800`, `text-primary`, `text-muted-foreground`); no hex in components. Serif (Playfair Display) for h1/h2 only; min text size 12 px; one h1 per page; skip link + landmarks; visible focus ring.
- SEO: every public page passes `title`, `description`, canonical-safe URL, and JSON-LD where meaningful via layout props; private routes are `noindex` (middleware). Page queries (`getPostPage`, `getDepartmentPage`, `getPostsPage` in `queries.ts`) return a `PageSeo` built by `src/lib/seo.ts` (`siteUrl`, `canonicalHref`, single description clamp `metaDescription`); pages pass it through instead of assembling SEO props. List filters for `/posts` and `/downloads` come from `src/lib/post-filters.ts`. Keep public pages free of admin bundles; hydrate islands only where needed.
- No server filesystem or in-process state (the app runs as serverless functions on Vercel): no `Astro.session`, no on-disk caches/uploads outside the `local` driver. Toasts go through `flash()` (`action-guard.ts`) = short-lived httpOnly `sic_flash` cookie read by `takeFlash` in `AppLayout`; auth rate limits use Better Auth `storage: 'database'` (`auth_rate_limits`), and app limits (password checks, contact form, uploads) use `consumeRateLimit` on the same table under `app:` keys. Current-password checks go through `assertPassword` (`actions/account.ts`); changing the email requires it.
- Adapter: `@astrojs/node` standalone by default; `@astrojs/vercel` when `VERCEL` is set or `ASTRO_ADAPTER=vercel` (`astro.config.mjs`). `vercel.json` builds with `node scripts/prisma-schema.mjs && prisma generate && astro build` and never migrates: CI runs `prisma migrate deploy` first. Add new migrations for every provider that has a `prisma/migrations/<provider>/` folder (sqlite, postgresql), with names sorting after existing ones.
- Production admin bootstrap: `prisma/create-admin.ts` (`ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD` or TTY prompt; ≥ 12 chars). Local/self-hosted stays available; S3 is the storage backend on Vercel. No placeholder content or images; missing imagery renders a token-coloured fallback.
